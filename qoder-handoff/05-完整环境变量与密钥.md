## 4. 三处真实冲突与裁决（以运行中容器为准）

- **C1 `DATABASE_URL` 两个值**：`.secrets:20` = `postgresql://<user>:<pwd>@localhost:5432/layoverjoy?schema=public`；compose:42 = 同一 DB 但主机名 `db`（容器网内）。
  **裁决**：容器内以后者为准（compose `environment` > `env_file`）；前者留给「后端不进 Docker、本机 `nest start` 直跑」和 vitest 集成路径。**两个都要保留，别删。** 本机用户口令：DB 是**纯本地容器**，账密写在 `docker-compose.yml:11-13`（`layoverjoy` / 本地口令 / `layoverjoy`），该口令已在 Git 跟踪文件里 —— 它只保护本机开发库，**不得**用于任何真实环境。
- **C2 `NOSANA_OPENAI_BASE_URL` 三处来源**：`.secrets:8`、compose:51 硬编码默认 `${NOSANA_OPENAI_BASE_URL:-https://3F7Zo…nos.ci/v1}`、宿主 shell export。
  **裁决**：实际生效 = **compose 里的值**（`environment` 覆盖 `env_file`），而 compose 的值又受宿主 export 影响 → **这就是 KN-04 的坑**。当前生效部署是 qwen2.5-3b（`/v1/integrations` 显示 `deploymentIdTail=XW5811vR`，与 compose 默认一致；容器内 `env` 三项已逐一核对一致）。
  ⚠️ **交接当日 12:12–12:18 该部署曾全路径 503「Service Initializing」，12:18:18 自行恢复 200（1.06s）** —— GPU 实例休眠/冷启动，**不是配置错**（容器内三项与 `.secrets` 逐字一致），详见 `04` KN-07。
  ✅ **2026-08-30 12:34 复查已健**：`/health` 200、`/v1/models` 200（1.08s）、`/v1/chat/completions` 200（真实 completion）。⚠️ 另：**`NOSANA_DEPLOYMENT_URL` 指向的容器根路径 `/` 没有 handler，恒返回 503**（同一秒 `/health` 为 200），**绝不能用它探活**；正确探针：`B=$(grep NOSANA_OPENAI_BASE_URL ../.secrets/layoverjoy.env | cut -d= -f2-); curl -o /dev/null -w '%{http_code}\n' "${B%/v1}/health"`。演示前仍建议预热 + 探测。
  ⚠️ 若新账号换部署（例如在 Nosana 控制台重新起一个），**必须同时改 `.secrets:8` 与 compose:51 默认**，或干净 shell 下 `export` 后 `--force-recreate`；只改一处会出现「日志说 A、请求打 B」。
- **C3 `DAYTONA_MODE`**：compose:48 `${DAYTONA_MODE:-local-runner}` ← 宿主 shell 决定。演示真隔离时 `DAYTONA_MODE=live docker compose up -d --force-recreate api`，演示完请 `unset`。

```bash
# 1) 先确认密钥文件在位且完整（应输出 26）
grep -cE '^[A-Za-z_][A-Za-z0-9_]*=' /Users/zhengmin/Documents/黑客松/alibaba/.secrets/layoverjoy.env

# 2) 用指纹核对没有被改坏（对照 §1 表格；下面这条干跑会一次列出全部 26 个变量的 len + sha256-8）
bash scripts/export-env-bundle.sh
bash scripts/check-local-environment.sh --skip-tests

# 3) 需要一份整体明文交给新账号（自己执行，产物已 gitignore，用完删除）
bash scripts/export-env-bundle.sh --write && open qoder-handoff

# 4) 可选：项目根 .env.local（本机直跑后端时用；Docker 路径不需要它，compose 直接读 .secrets）
#    这条命令会复制真实密钥，请你自己执行、不要贴到任何聊天里
cp ../.secrets/layoverjoy.env ./.env.local

# 5) 起服务并校验
docker compose up -d --build && bash scripts/check-local-environment.sh --skip-tests
```

> 我**没有**替你生成 `.env.local` / `full-env-backup.txt` 这类明文密钥副本文件；`.env.local` 在当前运行方式下并非必需（compose 用 `env_file: ../.secrets/layoverjoy.env`）。上面第 4 步就是你要的那条命令，价值相同、风险由你自己控制。

## 8. 如果确认某密钥已泄露（比如你刚把它贴进了别的工具）

| 变量 | 轮换影响 | 操作 |
|---|---|---|
| `ATLAS_CLIENT_ID/SECRET` | 旧凭据立刻失效，Sandbox Search/Verify 中断 | 到 ATRIP/Atlas 控制台重签发 → 改 `.secrets:14-15` → `docker compose up -d --force-recreate api` → `bash scripts/check-local-environment.sh` |
| `JWT_SECRET` | **所有已登录会话失效**（App 需重新登录），DB 数据无损 | 改 `.secrets:17`（≥16 字符随机）→ 重建容器；建议顺手清 `RefreshToken` 表 |
| `DATA_ENCRYPTION_KEY` | ⚠️ **已加密的证件字段将无法解密** —— 换前必须先用旧钥导出/重加密 | 不要直接换；需要写一次性迁移脚本（旧钥解 → 新钥封）。黑客松范围内**建议不换** |
| `NOSANA_API_KEY` / `DAYTONA_API_KEY` | 计费与部署权限，立即失效 | 各自控制台 rotate |
| `SMTP_PASSWORD` | 邮件中断 | 向 ATRIP 管理员重置 |
| `ATLAS_WEBHOOK_SHARED_TOKEN` | 旧 URL 回调 401；`WEBHOOK_MODE=simulate` 下无实际影响 | 改 `.secrets:19` 即可 |
| 本地 PG 口令 | 仅本机开发库 | 同步改 `docker-compose.yml:11-13` + `.secrets:20`，并 `docker compose down -v` 会清库（**别在演示前干**） |
