# 01 · 产品目标与黑客松要求

## 1. 产品目标

**一句话（AGENTS.md / 09 号方案口径）**：LayoverJoy 是一个签证感知的 Agentic Stopover Planner，把原本匆忙的转机变成安全、透明、可预订的多日旅行。

- 产品名：`LayoverJoy`；中文口号「转机的乐趣」；Android 应用显示名已统一为英文 `LayoverJoy`（commit `d29998ed`）。
- 目标用户：持**中国普通护照**、在东南亚/东北亚枢纽中转的旅客（MVP 单一护照国，不做多护照交集）。
- 核心价值主张三段式，缺一不可：
  1. **能不能玩** —— 确定性入境规则引擎（不是 LLM 判断）；
  2. **值不值得玩** —— 净体验窗口 + 中转便利度分（完全确定性，AI 只做叙事）；
  3. **玩得了就订得了** —— Atlas Sandbox 搜索/验价 + 双独立单程订单 + 模拟支付与退款。
- 与 OTA 的差异：OTA 按「最便宜/最快」排中转；LayoverJoy 按「证件可入境 + 真实可用游玩时间 + 全成本 + 独立机票风险」排中转。

## 3. 不能随意修改的产品约束（AGENTS.md 摘录，全部为硬约束）

- **固定技术栈**：Kotlin + Jetpack Compose + Material 3；NestJS + TypeScript；PostgreSQL；Redis；Docker Compose；Daytona；Nosana；Atlas/ATRIP Sandbox。
- **双语**：`ui/i18n/L10n.kt` 词典 + Compose 快照状态，切换即时生效不重启；入口在「我的」页。**禁止硬编码单语字符串**，枚举标签用 code→i18n key 映射、只向后端传 code；改完必须 `bash scripts/check-i18n.sh`。
- **签证与证件安全**：结论必须带 `ruleId / sourceUrl / checkedAt / confidence`；App 必须提示最终决定权属于航空公司与边境机关；MVP **不保存护照号、签证号、证件照片**；Sandbox 输入不得含姓名/邮箱/护照号/签证号；日志不得记证件明文。
- **搜索与规划配额**：实时最多评估 3 个中转城市；每城最多 2 个停留天数；单次规划 ≤10 个 Atlas Search；并发 ≤3；单请求超时 8s；软超时 20s / 硬超时 30s；部分失败返回 `PARTIAL`；只对用户最终选中的 Offer 执行 Verify；Search Cache 15 分钟；Daytona 临时 Sandbox 在成功/失败/超时路径都必须清理。
- **预订**：多日 Stopover = 两张独立单程订单；Order/Pay **不自动重试**；第一张成功第二张失败 → `PARTIAL_BOOKING`；MVP 补偿只做明确标识的模拟退款；不承诺联程保护；每次涨价需用户重新确认。
- **UI**：以 `qoder-input/ui-reference/flight-monitor-app-ui.html` 为视觉与流程依据；消费者 App，**不得**做成管理后台/桌面 Dashboard；所有 Sandbox 价格显示测试环境标签；运行证据只展示结构化工具摘要，**不展示模型思维链**。
- **数据模型**：MVP 每用户只有一本 ACTIVE 主护照，可有多条签证/居留许可；Flight Leg 从 1 开始编号；直飞 1 个 Leg、Stopover 2 个有序 Leg；`BookingIntent` 保存不可变 `planSnapshot + schemaVersion + capturedAt`；直飞基准字段名 `baselineDirectOfferSnapshotId`。
- **Secret 安全**：见 00 号文（真实密钥永不写入源码/Markdown/Fixture/APK/日志）。

## 4. 完成门禁（AGENTS.md §11 —— 「能不能对外说真实 Demo 完成」的判据）

代码可以在外部 Preflight 为 `PENDING` 时用 Mock Provider 生成，但**不得宣称真实 Sandbox Demo 已完成**。真实 Demo 需同时满足：Atlas 官方测试路线 Search 通过、Atlas 脱敏 Search Fixture 已存、**Nosana 真实 Endpoint 请求通过并存脱敏 Fixture**、Daytona Sandbox Job 真实运行、App 中 Sandbox 标识正确、当前注册用户能收到邮件、本地 Docker 可回退启动。

当前达成情况见 `03-已完成功能.md` 末尾的门禁对照表（唯一持续风险项：外部收件人邮件被 SMTP 中继拒绝，见 `04`、`08`）。

## 5. 3 分钟视频脚本骨架（基于 09 号 §9 两分钟脚本扩展）

| 秒段 | 内容 | 界面 |
|---|---|---|
| 0–20 | 痛点：OTA 把转机当等待 | 首页 Visa-Aware 机会卡 |
| 20–45 | 输入：中国普通护照 + 已有美签；城市/机场选择器（含 SHA 多机场消歧） | 搜索页 + 地点选择页 |
| 45–80 | Agent 执行：3 个候选城市并行评估、证件规则筛除、运行证据 | 结果页「为什么只留下这些城市」 |
| 80–135 | 结果与价值：净体验窗口 7 档标签、便利度分、AI 推荐卡（城市优势/小行程/取舍）、Sandbox 报价标签 | 方案详情页 |
| 135–165 | 闭环：价格监控 → 邮件到当前用户邮箱 → 双订单 Order/Verify → 模拟支付 → 第二单失败演示 `PARTIAL_BOOKING` + 模拟退款 | 通知/行程/订单页 |
| 165–180 | 收尾：Atlas 让行程可交易、Daytona 让 Agent 安全并行、Nosana 让结果可读 | 三系统同框 |

拍摄注意（性能相关，见 08）：Nosana 单次推理实测约 2s（中）/ 4s（英），但 3b 模型对长 Prompt 遵循度有限，多数请求走 **Validator → 丰富模板降级**（UI 同构、观众看不出差别）。录视频时**建议先手动预热一次**，避免现场等待；不要为了显得「AI 很强」而展示思维链（UI 本就不展示，符合约束）。
