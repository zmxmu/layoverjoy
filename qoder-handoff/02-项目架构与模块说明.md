# 02 · 项目架构与模块说明

## 1. 七个运行组件

| 组件 | 技术 | 角色 | 真实 / Mock |
|---|---|---|---|
| Android 客户端 | Kotlin + Jetpack Compose + Material 3 + Retrofit + kotlinx.serialization + DataStore | 消费者 App，包名 `com.yuanhe.layoverjoy` | 全真实渲染，Base URL 运行期可切（开发页） |

| PostgreSQL | `postgres:16.6-alpine3.20`，容器 `project-db-1`，宿主 5432 | 用户/证件/规则/快照/订单/通知持久化 | 真实 |
| Redis | `redis:7.4-alpine3.20`，容器 `project-redis-1`，宿主 6379 | 搜索缓存（15min）、限流、任务协调 | 真实；**连不上时 `RedisService` 自动降级进程内 Map**（不报错，注意区分） |
| Atlas / ATRIP | `https://sandbox.atriptech.com` | 航班 Search + 验价 Verify | **真实 Sandbox**（模拟报价） |

Worker：`monitor-worker`（同镜像，`command: ["worker"]`，入口 `backend/src/worker.ts`）跑价格监控轮询与通知投递。

## 2. 请求主链路

```
Android (Net.api)
  └─ POST /v1/searches ──► SearchOrchestrator
                             ├─ locations: shared/catalog/city-airport-catalog（V2 resolveSelection，多机场受控展开 ≤3/端）
                             ├─ 候选城市 ≤3 × 停留天数 ≤2
                             ├─ entry-rules v2 预筛（INELIGIBLE 不调 Atlas；NEEDS_REVIEW 不冒充可预订）
                             ├─ Atlas Search（并发 ≤3，单请求 8s，软 20s / 硬 30s，≤10 次）
                             ├─ planning-jobs（Daytona local-runner / live 沙箱，产出 candidate-result + evidence）
                             └─ 落库 StopoverPlan + FlightOfferSnapshot + EligibilitySnapshot
  └─ GET /v1/plans/{id} ──► 方案详情（含 experienceContext：净体验窗口 + 便利度，无模型参与）
  └─ POST /v1/plans/{id}/explanation ─► ExperienceContextBuilder → EaseScore
                                         → Nosana explainRich → RichNarrativeValidator
                                         → (失败重试1次) → RichTemplateNarrator 降级
  └─ POST /v1/bookings ─► BOOKING 模式重评资格 → Order 1 / Order 2（独立单程，mock）→ mock-pay → Webhook → 通知
```

### 3.1 `entry-rules/v2/`（入境规则引擎，唯一事实源）

| 文件 | 作用 |
|---|---|
| `data/cn-ordinary-passport-entry-rules.v2.json` | **v2 JSON = 唯一事实源**（schema 2.0.0，24 条规则） |
| `schema-validator.ts` | 启动时结构/语义校验，失败即拒绝激活（绝不部分激活） |
| `catalog-loader.ts` | checksum（sha256-16）+ `importDataset` 事务 + `activate/rollback` + `reviewQueue` |
| `facts.ts` | 事实抽取（护照有效期、证件集合、历史停留等） |
| `matcher.ts` | 规则匹配；`isHard()` = `VALID_FOR_DAYS` 或 `traveler.history.*` 的 LTE/GTE → 硬事实失败即 INELIGIBLE |
| `aggregator.ts` | 优先级：负向规则 TRUE → hard FALSE → relax → TRUE |
| `freshness.ts` | 临时政策 `effectiveTo` 零点自动失效 |
| `assess.service.ts` | 搜索/预订两种模式；合并用户证件钱包；三值逻辑 `UNKNOWN→missingFacts→NEEDS_INFO` |

核心语义（**不要「优化」掉**）：
- 三值逻辑：未知事实 → `missingFacts` → `NEEDS_INFO`，不猜。
- 搜索期若**仅**缺 `documents.*` / `traveler.history.*` 类材料或声明 → 放宽为规则自身搜索决策 + `MATERIAL_PENDING_VERIFY`（CONDITIONAL），但**预订至少要 `NEEDS_REVIEW`**；`TRANSIT_TOUR_PROGRAM` 类别**不放宽**。
- 负向规则优先：如「菲律宾第三国过境需提前办签」TRUE → 直接 `INELIGIBLE`，覆盖 14 天免签。
- 评估中转地时 facts 的 `destination.country` 必须优先取 `stopover.country`（否则航段末点与评估对象不一致，规则叶子误判 FALSE —— 已踩过的坑）。

### 3.2 `explanations/`（AI 价值解读，14 号方案）

| 文件 | 作用 |
|---|---|
| `data/city-experience-catalog.zh-en.json` | 版本化城市资料（MVP 五城 KUL/BKK/HKG/SIN/ICN），机场交通带官方运营方 URL + `verifiedAt` |
| `experience-context.builder.ts` | IANA 时区**净体验窗口**：gross = leg2.dep − leg1.arr；mandatory = 入境 90 + 往返机场(资料库中位数×2，缺省 45→LOW 置信) + 提前候机 180 + 独立票 60 + 重托运 45 + 夜晚数×420；7 档标签；`contextVersion '2.0'`、`promptVersion 'stopover-value-v2'` |
| `stopover-ease-score.ts` | 便利度：基础 50，§7.1 表加减分，clamp 0–100，四档 `EASY/SMOOTH/PLAN_CAREFULLY/DEMANDING`，输出 `positiveReasonCodes/cautionReasonCodes` |
| `rich-narrative.validator.ts` | 拒绝越界输出：金额（`MONEY_RE`）、模型/硬件归属（`TECH_RE`）、复述天数/小时/JoyScore（`REPEAT_RE`)、「」内区域必须⊆`allowedAreas`、`evidenceKeys` ⊆ 输入、语言一致（zh 必含 CJK / en 禁 CJK）、签证保证语 |
| `rich-template-narrator.ts` | 与真模型**同结构**的确定性降级叙事（verdict 规则 + 兴趣加权优势 + 贪心三时段小行程 + ease 叙述 + 取舍）；模板自身输出也必须过 validator |
| `nosana.service.ts` | `explainRich(cacheKey, ctx, lang)` **single-flight**（`inflight` Map）；native `/api/chat` 优先，404/405 回退 OpenAI `/v1/chat/completions`；`sanitizeContextForPrompt()` 不含分钟数/金额/PII；单行结构化完成日志（provider/latency/fallback/promptVersion） |

缓存键：`SHA-256(planId|lang|行程|interests|pace|catalogVersion|promptVersion).slice(0,24)`。

### 3.3 配置系统三套并存（一个约定：值只从环境/密钥库来）

1. **后端**：`process.env` → Zod `EnvSchema` → `loadEnv()`（冻结、缓存）。`package.json` **不依赖 dotenv**，变量必须由容器/外部 `.env` 提供。
2. **Atlas CLI**（`../atlas-flight-booking-skill`）：`platformdirs` 定位 `~/.config/atlas-flight-booking/config.json`，`portalocker` + 临时文件 `os.replace` 原子写，密钥走 `keyring`；`save_customer_mode` 只接受 `prod|sandbox`。
3. **Android**：Gradle `buildConfigField` 编译期注入 `DEFAULT_BASE_URL` / `DEFAULT_REMOTE_URL` / `DEFAULT_PREVIEW_TOKEN`；运行期 DataStore 覆盖（`ServerEnv.localServerUrl()`：模拟器 `10.0.2.2`、真机/本机 `127.0.0.1`）。

## 6. 数据模型（Prisma，表名 = PascalCase 需带引号）

26 个 model：`User, RefreshToken, TravelDocument, EntryRule(旧只读), SearchRun, FlightOfferSnapshot, EligibilitySnapshot, EntryRuleSet, EntryRuleV2, EntryRuleSource, EligibilityAssessment, EligibilityEvidenceSnapshot, StopoverPlan, PlanExplanation, MonitorRule, Notification, NotificationDelivery, BookingIntent, FlightOrder, AtlasWebhookEvent, AuditEvent, PlanningJob, PlanningJobCandidate` + migration 表。

MVP 不变量：单用户仅一本 `ACTIVE` 主护照；签证/居留可多条；`legNo` 从 1 起；`BookingIntent` 存不可变 `planSnapshot + schemaVersion + capturedAt`；直飞基准字段 `baselineDirectOfferSnapshotId` 不与方案自身报价混用。`TravelDocument` 为 v2 增了 `entryCount / verificationMode / issuerCountry / usedBefore`。

## 7. 本地/Mock 与真实 API 的边界（对外表述必须准确）

| 功能 | 状态 | 依据 |
|---|---|---|
